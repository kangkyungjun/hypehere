## 0. 한 줄 진단

**히어로가 없어서가 아니라, 히어로가 기본 상태에서 렌더되지 않아서다.**

```dart
// lib/widgets/dashboard/indices_bar_widget.dart:128-136
style: (isSelected ? AppTypography.priceLarge   // 31px ← 히어로
                   : AppTypography.priceCard)   // 20px ← 실제로 보이는 것
```

`isSelected`는 `selectedIndex`에서 오고(`:52`), `dashboard_screen.dart:62`는
`String? _selectedIndex;` — **초기화 없는 null**이다. 사용자가 지수를 탭하기 전까지
3개 카드 전부 20px로 그려진다. 앱을 켠 사용자는 **100% 확률로 히어로를 못 본다.**

커밋 `abf0d47`의 메시지는 *"화면별 히어로 재배정 — 토큰만 바꿔선 홈이 안 바뀐다"* 였다.
재배정은 했는데 **기본값이 꺼진 상태 뒤에 숨겼다.** 이것이 54커밋 + 20커밋을 더 하고도
체감이 없었던 단일 최대 원인이다.

## 1. 계측 — "글씨가 작다"의 실제 크기

두 캡쳐의 기기 폭이 다르다(헤이딜러 1080 / 마켓랜즈 1206). 글자 **잉크 높이를 화면 폭
대비 %로 정규화**해 비교한다. 이 값은 기기에 무관하다.

| 요소 | 잉크 높이 | 화면 폭 대비 |
|---|--:|--:|
| **헤이딜러** 히어로 `3,500~3,680` | 83px | **7.69%** |
| **헤이딜러** 섹션 타이틀 | 55px | 5.09% |
| **헤이딜러** 리스트 본문 / KV 행 | 41px | 3.80% |
| **마켓랜즈** 앱바 `MarketLens` | 37px | 3.07% |
| **마켓랜즈** 지수 값 `535.06` | 28px | **2.32%** |
| **마켓랜즈** 지수 라벨 `Dow Jones` | 20px | 1.66% |

> **헤이딜러의 본문(3.80%)이 우리 앱의 가장 큰 숫자(2.32%)보다 크다.**
> 우리 화면에는 히어로가 없는 게 아니라, 레퍼런스 기준으로는 **본문조차 없다.**

(`03-similar-expanded.jpg`, y=726→797→868→940→1012). 우리는 불규칙하다.

> **결정 필요 A**: 스케일을 코드(부록 A)로 확정하고 문서를 정정할 것인가,
> 아니면 `bodySmall`만 12로 되돌릴 것인가. **어느 쪽이든 문서 3종을 한 번에 맞춰야 한다.**
> 권고는 **코드 확정 + 문서 정정** — 부록 A는 실측 기반이고, 183 호출부를 되돌리는 것은
> 이득 없이 위험만 크다.

## 4. 통일 규약 — 이 개편이 만드는 전 화면 기준

앞으로 모든 화면은 아래를 만족해야 한다. 이것이 사용자가 말한 "통일화"의 내용이다.

### 규약 1 — 화면당 히어로 1개, 그것은 **숫자 또는 판정**
- 제목이 히어로보다 크면 안 된다. 레퍼런스 비율은 **타이틀 : 히어로 = 1 : 1.72**
- 현재 홈은 22 : 20 = **1 : 0.91**로 역전돼 있다
- 히어로는 **조건부 상태 뒤에 숨기지 않는다** (H0의 교훈)

### 규약 2 — 몸통(KV·메타)은 크기를 벌리지 않고 **색·굵기로만** 나눈다
- 레퍼런스의 라벨:값 크기비는 **1.04배**(거의 같음). 위계는 색 2.6배 + 굵기
- 우리는 반대로 1.07~1.15배씩 잘게 벌려서 **아무 위계도 안 생긴다**
- ⚠️ 현재 `kvLabel`(14) vs `kvValue`(15)가 **1px 벌어져 있다** — 스펙 §2가 확정한
  핵심 기법이 무력화됨. **둘 다 14 또는 둘 다 15로** 맞출 것

### 규약 3 — 읽기 단계는 4개, 인접비 최소 1.2배
```
18 (행 히어로/카드 제목) · 16 (본문 헤드라인) · 13 (라벨) · 11 (메타·배지·축)
+ 화면 히어로 31 또는 37 (화면당 1개)
```
현재 16/15/14/13이 **1.23배 폭 안에 갇혀 사실상 한 크기**다. 15와 14를 몸통에서 뺀다.

### 규약 4 — 제목은 2종
- `SectionHeader`(`section_header.dart:86`)와 `MlCardTitle`(`ml_expandable_card.dart:220`)이
  **둘 다 `sectionTitle`(22)** 을 쓰고, `cardTitle`은 18이라 현재 **3종**이다
- **`MlCardTitle`을 `cardTitle`(18)로 내리는 한 줄**이 P3의 "2종" 목표를 막고 있는 유일한 장애물
- 스펙 §5의 "10개 전부 동일 렌더링으로 수렴" 주장은 이 한 줄 때문에 **거짓**

### 규약 5 — 색은 3역할만
- **블루** = 탭 가능 + 비방향성 히어로 + 차트 주 라인
- **녹/적** = 부호가 있는 것만 (변동·손익·%)
- **검정** = 사실 (현재가·수량·날짜·금리 수준). 강조는 크기·굵기로
- 현재 위반: `macro_strip_widget.dart:116-118` 국채금리가 빨강

### 규약 6 — 여백은 `8 < 12 < 20`
`카드 안쪽 블록 ≤8 < 카드 사이 12 < 섹션 사이 20`.
**`AppSpacing` 숫자는 동결**, 밀도는 **`AppDensity`**(`MlDensity` 아님)만 만진다.

### 규약 7 — 프리셋을 쓴다, 크기 숫자만 빌려 쓰지 않는다


못 받는다.** 크기는 토큰화됐지만(하드코딩 `fontSize:` 숫자는 `trend_modal.dart:430`
단 1건) **행간이 기본값으로 흩어져 있다.** 이것이 "1px 간격에 갇힌 평면"의 현재 형태다.

→ **§2-3의 토큰화가 이번 개편의 선결 조건인 이유.**

### 7-2. 다만 `WebViewScreen`은 버전과 무관하게 부실했다 — 고쳤다

개편 전 55줄, 등록된 콜백은 `onPageFinished` **단 하나**였다.

| 결함 | 증상 | 조치 |
|---|---|---|
| `onWebResourceError`/`onHttpError` 없음 | **오프라인·404에서 영구 흰 화면** (에러 시에도 `onPageFinished`가 발화해 스피너만 꺼짐) | `ErrorStateView` + 재시도. 메인 프레임만 판정 |
| `PopScope` 없음 | 안드로이드 백 1회에 **웹 히스토리 통째로 소실** | `canGoBack`/`goBack` 선소비 |
| `onNavigationRequest` 없음 | `mailto:`·`tel:`·`intent://` 링크가 **죽음**(Android 에러 페이지 / iOS 무반응) | 비-http 스킴을 OS에 위임 + 실패 시 토스트 |
| 로딩 단방향 | 리다이렉트 중간에 스피너가 꺼져 **빈 화면 응시**, 이후 탐색은 무피드백 | `onPageStarted`/`onProgress` → 상단 진행바 |
| 탈출구 없음 | 페이월 만나면 **선택지 0** | 새로고침 + 브라우저로 열기 + 공유 |
| 도메인 미표시 | 제목이 `"원문 기사 보기"`(동사구) — 리다이렉트로 광고 도메인에 가도 모름 | 앱바에 **출처명 + 호스트** 2단 |
| 다크 흰 플래시 | 매 로드 번쩍임 | `setBackgroundColor` |
| 스피너가 이전 페이지 위에 겹침 | 이중 노출 | **첫 로드에만** 전면 스크림 |

플랫폼 선언도 추가했다 — 없으면 외부 위임이 Android 11+/iOS에서 실패한다:
- `android/app/src/main/AndroidManifest.xml` `<queries>`에 VIEW(https)·VIEW(mailto)·DIAL(tel)
- `ios/Runner/Info.plist`에 `LSApplicationQueriesSchemes` (신규)

l10n 4키 × 5로케일 추가. `flutter analyze` 0 issues, l10n 커버리지 테스트 통과.

### 7-3. 남은 웹뷰 항목

**`target=_blank` / `window.open`이 iOS에서 무반응.** 기사 하단 "관련 기사" 링크
대부분이 이 형태다. Android는 `setSupportMultipleWindows(false)` 기본값 덕에 메인
프레임으로 떨어져 동작하므로 **플랫폼 간 동작이 다르다.**

해결하려면 `webview_flutter_android` / `webview_flutter_wkwebview`를 **직접 의존성으로
승격**해야 한다(현재는 전이 의존성). 새 의존성 추가라 별도 승인 항목으로 남긴다.

## 7.6 ⚠️ 1.3배 캡쳐가 잡아낸 회귀 (2026-09-30)

스크린샷을 1.0배로만 보면 **절대 안 보이는** 버그가 있었다. 섹터 차트에서
막대가 영역을 넘어 `-1%` 라벨 위로 번지고 아래로 흘러내렸다.

### 원인 1 — 고정 px가 `textScaler`를 무시했다 (절반은 이 계획의 책임)

| 박스 | 1.0배 필요 | 1.3배 필요 | 판정 |
|---|--:|--:|---|
| `_labelHeight = 16` | 13.2 | **17.2** | ❌ |
| `_nameHeight = 28` | 25.3 | **32.9** | ❌ |

U3의 검산 *"11 × 1.15 × 2줄 = 25.3 < 28 → 세로 비용 0"* 은 **배율을 곱하지
않은 계산**이었다. `_nameHeight`는 개편 전에도 이미 넘치고 있었고
(micro 10 × 1.3 × 1.15 × 2 = 29.9 > 28), U3가 `_labelHeight`까지 넘치게 했다.

> **규칙 추가**: 고정 높이 박스 안에 텍스트를 넣을 때의 검산은 **반드시
> `× textScaler 상한(1.3)`을 포함한다.** 이 계획서의 다른 검산들
> (`mainAxisExtent: 150`, `Tab(height: 32)`)은 1.3배를 포함했는데 U3만 빠졌다.

### 원인 2 — 렌더와 계산이 다른 행간을 봤다

배율 연동으로 고친 뒤에도 2.4px가 남았다. 라벨 `Text`에 명시적 `height`가
없어 **Pretendard 기본 행간(1.2보다 크다)으로 렌더**되는데 계산은 1.2를
가정하고 있었다. 렌더와 계산이 **같은 상수**(`labelLineHeight`)를 보도록 맞췄다.

### 왜 기존 검증이 못 잡았나

`flutter analyze`도 `flutter test`도 통과했다. **`RenderFlex` 오버플로는
예외가 아니라 `FlutterError`로 보고**되기 때문에 `tester.takeException()`에
걸리지 않는다. 신규 `test/sector_bar_chart_layout_test.dart`가 그것까지 본다.

### 남은 섹터 차트 문제 2건 (미착수)

1. **상단 44.6px 죽은 공간** — 0 기준선이 위에서 `labelHeight + 40`에 고정돼
   있어, 하락장(양수 폭이 작을 때) 상단 56px 중 44.6px(차트의 32%)이 빈다.
   여백 타이트 선호에 정면으로 어긋난다. → 양/음 최대값 비율로 위아래 예산을
   나누면 해결된다.
2. **섹터명 단어 중간 끊김** — `Consum / er Stap…`. 7열에 영문 원문을 넣어
   가독성이 없다. 서버 원문(`sector.sector`)에 l10n·축약 매핑이 없다.
