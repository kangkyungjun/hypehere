### ★ 결정적 발견 1 — 스케일 진폭이 크다
최소 13 ↔ 최대 40. **비율 약 3.1배.**
우리 앱은 최소 8(chartMicro) ↔ 최대 30(heroMedium) = 3.75배지만,
**실사용 구간이 10~18에 몰려 있어** 체감 진폭은 1.8배 수준. 이게 밋밋함의 정체다.

### ★ 결정적 발견 2 — KV는 크기가 아니라 색·굵기로 나눈다
`사고 / 완전무사고`, `모델명 / BMW 5시리즈` — **라벨과 값의 크기가 사실상 같다(15~17).**
차이는 오직 **색(뮤트 ↔ 검정)** 과 **굵기(Regular ↔ Medium/SemiBold)**.
→ 여백을 늘리지 않고 위계를 만드는 정확한 방법. 사용자의 "타이트 선호"와 완전히 양립.

### ★ 결정적 발견 3 — "큰 값 + 작은 단위" 비율
- 히어로: `3,500~3,680`(36–40) : `만원`(20–24) → **약 1.7 : 1**
- 리스트: `3,230`(21) : `만원`(13) → **약 1.6 : 1**
단위는 같은 색 계열이되 한 단계 뮤트, 굵기는 한 단계 낮춤. 여백 추가 0.

### ★ 결정적 발견 5 — 값은 **좌측 정렬**이다 (기존 계획서 오류)
`docs/UIUX_REFERENCE_REDESIGN_PLAN.md` §5-A는 "라벨 좌·**값 우측정렬**"이라고 적었는데,
캡쳐 ①③을 보면 **KV 상세 행의 값은 전부 좌측 정렬**이고, 라벨 열이 고정폭이라
값의 시작 x가 세로로 정렬되어 리듬이 생긴다.
**우측 정렬은 리스트 카드의 가격(히어로 숫자) 한 곳뿐.**
→ 규칙: **KV 상세 = 좌측정렬 / 리스트 요약의 대표 숫자 = 우측정렬.**

## 7. 기존 계획서 대비 정정 사항

1. **§5-A "값 우측정렬" → 오류.** KV 상세는 좌측정렬(§3 결정적 발견 5).
2. **§3.3 "타입 스케일 15단계 유지" → 폐기.** 레퍼런스 진폭 3.1배를 재현하려면 스케일 상향 필수.
3. **홈택스 DNA 잔재 없음 확인** — 정본은 헤이딜러 3장뿐.
4. **§3.4 "블루는 절대 가격에 안 씀" → 재검토 필요.** 레퍼런스는 히어로 가격을 블루로 쓴다.
   우리는 방향성(등락)만 녹적이므로, **비방향성 히어로(현재가·목표가·시총)에 블루 적용 가능**.
   단 "블루=탭 가능" 신호와 충돌 여부는 결정 필요 → 사용자 승인 항목.

# 부록 A — 화면폭 대비 비례 분석 (2026-08-30 재측정, **이것이 정본**)

## 왜 다시 쟀나
본문 §1은 "환산계수 2.24(412dp 가정)"로 절대 dp를 추정했다. 기기 폭 가정이 틀리면
전부 틀어지고, 실제로 적용 결과가 레퍼런스와 눈에 띄게 달랐다.

**비율은 기기에 무관하다.** 그래서 모든 값을 **화면폭 대비 천분율(‰)** 로 다시 재고,
Flutter 논리 폭을 곱해 쓰는 방식으로 바꾼다.

```
dp = (요소 크기 ‰) / 1000 × (화면 논리 폭)
글자 em ≈ cap-height / 0.72     (한글 Pretendard/Apple SD Gothic 계열)
```

## 미적용 — 판단 근거를 남긴다

- **저알파 블루 산점도**: 레퍼런스의 산점은 "비슷한 매물"의 분포다. 우리 가격 차트는
  단일 시계열이라 대응 데이터가 없다. → 애널리스트 목표가 분포·동종업계 밸류에이션
  차트에 적용하는 게 맞다(별건).
- **Y축 절단 물결(squiggle)**: 레퍼런스는 `0만원`과 `2,500만원` 사이에 물결을 그려 축이
  잘렸음을 알린다. 우리 차트는 **0 라벨을 아예 그리지 않으므로**(`minY = 최저가 − 여유`)
  0부터 시작한다는 오해가 생기지 않는다. 물결의 목적이 이미 충족되어 생략.
